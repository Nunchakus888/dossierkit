# Unlisted Agent CV

The optional `profiles/{profileId}/cv-agent.yaml` supplies a separate presentation at `/zh/cv-agent/` and `/en/cv-agent/`. The legacy `/cv/`, `CVLayout`, profile files, existing resumes and public collections are unchanged. Identity, job titles, periods and metric values come from the canonical ProfilePack. The optional `educationSourceSchool` selects one canonical education record for this CV; the default profile shows the earlier college degree and omits its later online program. Curated summaries, architecture and research live only in this opt-in view; they are never added to ProfilePack or its JSON export. Experience entries state product responsibility and outcomes; the separate architecture section carries implementation detail. Architecture status remains in the authoring data and the HTML `data-claim-status` attribute; the CV does not display status badges. The HTML advertises an unlisted UTF-8 plain-text counterpart at `/{locale}/cv-agent.txt`, generated from the same data for readers that extract PDF text unreliably.

## Visibility

There are no inbound navigation, homepage, role, note or case links. The standalone layout has no global navigation, analytics/page-view registration or Pagefind body. Sitemap filtering, page metadata and scoped Cloudflare `X-Robots-Tag` headers exclude indexing; PDF files use `/resumes/cv-agent/`. `Referrer-Policy: no-referrer` avoids passing the unlisted URL to research links or other origins. Do not add robots.txt Disallow rules: crawlers must fetch the page to observe noindex. This is link sharing, not authentication; anyone holding the URL can open or forward it.

Current business metrics are carried from the existing career material, not newly measured. CLI/Channel-specific adapters, inbound Cowork MCP service, and group-chat collaboration are presented as designs, not shipped features. English uses reviewed counterparts where available, otherwise labels and links the Chinese original.

## Isolated signature and web-only analytics

The Agent CV has its own minimal footer, visually derived from the main Notes footer (shared Pacifico signature font and thin gradient rule). The name opens flush-left; the smaller, matching green (`#247f74`) Pacifico signature closes flush-right. Use a **single shared motto** from `navigation.yaml → footer.tagline` (currently `The Emergence of Everything`) for web, browser Print / Save as PDF, and downloaded PDFs. The web footer keeps the eye/page-view count to its left in a right-aligned, non-wrapping row, including mobile widths. Printed documents hide the eye/count. The final print page uses a dedicated fixed-height A4 content frame (`266mm`, inside 14mm top/bottom margins) with a flex spacer that pins the motto flush-right at the bottom of **page 2**, independent of preceding content length; it must not repeat on page one or produce a blank third page. Tests check remaining clearance above the footer, final position, two A4 pages and one consistent motto. No navigation, privacy link, site totals, extra tracking or Notes UI is added.

On production web views, the footer reuses the existing first-party D1 counter, registering only `/zh/cv-agent` and `/en/cv-agent` as countable, noindex routes in the server-side allowlist. It shows a quiet page-view count when the counter is enabled and healthy; no counter or fake zero is displayed if disabled. Raw IPs or contact paths are never displayed. Aggregate analyses remain available from the existing read-only `/api/views?mode=summary&path=/zh/cv-agent/` and `mode=sources&period=7d&path=/zh/cv-agent/` endpoints (equivalent for English), including trends, PV/UV and referral attribution. The public top-page rankings explicitly exclude unlisted CVs. This is anonymized aggregate analytics, not authenticated/private analytics and not proof of a unique human per view; browser opt-outs and anti-bot checks still apply. In offline PDF export the client can never report a production page view.

## Validation and export

```sh
pnpm exec tsx scripts/test-cv-agent.ts
CV_AGENT_PDF=1 pnpm build
pnpm exec playwright install --with-deps chromium
# A CJK font package, such as fonts-noto-cjk on Ubuntu, is required for Chinese export.
pnpm exec tsx scripts/generate-cv-agent-pdf.ts
node scripts/verify-cv-agent-build.mjs --require-pdf
```

CI runs these checks before deployment. The optional `pdfFilenameBase` in `cv-agent.yaml` controls the descriptive download name and the public PDF basename, adding `-zh.pdf` / `-en.pdf` to avoid language collisions. For the default profile these are `George-AI Agent开发专家-zh.pdf` and `George-AI Agent开发专家-en.pdf`. Public URLs percent-encode the filename; the export also keeps the previous `george-zh.pdf` and `george-en.pdf` PDFs working as aliases for already shared links. The print header keeps three icon-only links (email, GitHub, canonical online CV) with inline SVGs; no contact URL or email text is displayed. Web icons retain hover titles and accessible labels. Their visible 18px controls sit flush with the content edge, while transparent pseudo-elements provide non-overlapping 44×44px hit targets; hover, active and tap states add no background fill, and keyboard focus stays visible. Print icons keep compact 22px clickable PDF link areas with URI annotations. PDF text extraction varies by renderer, so give LLM readers the UTF-8 plain-text URL when exact text matters. Without `CV_AGENT_PDF=1`, normal development builds show Print / Save as PDF but no ungenerated download link. Export writes only to the new dist namespace and a private CI review artifact; it never invokes or modifies the legacy PDF generator. Browser checks cover 320/390/1280px, both language PDFs must have two A4 pages, and build checks reject public inbound links, sitemap/JSON/feed exposure, missing notes or PDF targets, and Pagefind fragment leakage. Profiles without this optional file generate no Agent CV routes.
