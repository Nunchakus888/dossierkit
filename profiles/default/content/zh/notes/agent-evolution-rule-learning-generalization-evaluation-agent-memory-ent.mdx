**核心论点：自进化只有在未见任务重新组合训练阶段的原子规则时仍能提高确定性得分，才构成可测量的能力增长；在训练任务上变好最多证明记忆有效。**

## 为什么普通成功率会误导

Agent 可以把历史轨迹、失败反馈和业务说明写入持久状态，再用于相似任务。这种机制确实可能提高分数，但提升有三种完全不同的来源：记住答案、匹配表面模板、抽象并组合规则。只有第三种能够应对持续变化的企业流程。

GDPevo 的价值不在于再做一个排行榜，而在于改变训练集与测试集的关系。它覆盖 CRM、ERP、财务、医疗、法律和数据工作流；V1 包含 12 个任务组、120 个任务，每组有 5 个训练任务与 5 个留出测试任务。自动化流水线还能较快生成新的任务组，用于降低公开基准被记忆后的失真。

## 规则杂交如何区分记忆与泛化

规则杂交先把一条企业流程拆成原子约束，再把不同子集分散到训练任务，最后在测试任务中重新组合：

```text
业务流程
  → 原子规则 {权限、状态、金额、审计……}
  → 训练任务暴露不同子集
  → 留出任务重组规则
  → 确定性 Rubric 逐项计分
```

例如，训练任务分别暴露“黑名单优先级”和“金额超过阈值需审批”，测试任务同时触发两者。复制某个历史答案无法通过；Agent 必须保留规则、识别触发条件，并正确处理组合关系。

## 证据说明了什么

论文报告，四类 Agent 在不同监督方式下的留出集准确率最高提升 16.44 个百分点。这说明从经验更新持久状态可以带来真实迁移收益。但最佳演进系统仍明显低于 91.6% 的 fully informed oracle 上限，因此数据也反驳了“当前 Agent 已经能够可靠自我完善”的强结论。

更重要的是，GDPevo 使用确定性规则评分而非开放式主观判断。每个失分点能够回溯到具体规则，使评测既能给出总分，也能成为失败归因输入。

## 工程实现：把 Memory 从案例库升级为规则库

规则制品至少需要以下字段：触发条件、适用范围、优先级、冲突处理、证据来源、验证用例和失效时间。写入流程应为“轨迹 → 候选规则 → 人工或策略审查 → 留出评测 → 晋级”，而非把一次成功轨迹直接写进长期记忆。

评测集也要分层：同题回归验证修复，近邻任务验证迁移，新组合任务验证规则合成，时间切片任务验证政策变化。成本与准确率应同时记录，避免通过无限增加上下文换取表面提升。

## 反例、局限与适用边界

规则杂交依赖任务可被拆成相对明确的原子约束。需求含糊、目标冲突或依赖隐性经验时，确定性 Rubric 会低估真实判断难度。自动生成任务也可能带来模板偏差；跨语言、跨组织和长期政策变化仍需单独验证。Oracle 上限代表信息充分条件下的可达分数，不等于真实生产上限。

## 在七篇中的位置

Self-Evolving Coding Agent 给出进化闭环，GDPevo负责检验闭环是否产生迁移能力；Agent Runtime 保存规则版本与评测状态；PIMiner 用对抗样本检验错误规则是否被写入；Active-SWE 产生新的真实失败；SuperScout 为规则抽取提供高质量证据；MCP Stateless 让规则执行与外部工具调用保持解耦。
