## 核心判断

Self-Evolving Coding Agent 的核心不是让模型自动修改自己，而是让 Agent 系统能够基于真实失败持续优化 Harness、Memory、Skills、Tools 和流程控制。

## 背景问题

传统 Coding Agent 优化方式通常是：发现失败 -> 修改 Prompt -> 重新测试。但生产环境中失败来源复杂：可能是上下文不足、工具选择错误、验证缺失、状态管理问题，而不是模型能力不足。

## 核心思想

Agent 优化应该被视为持续学习系统：

Production Trace
-> Failure Classification
-> Candidate Improvement
-> Regression Evaluation
-> Release

关键不是提升单次 Benchmark，而是避免旧能力退化。

## 工程方法

建立三层评测：

1. Hard Contract
安全、权限、数据边界，必须 100% 通过。

2. Historical Regression
保证已解决问题不回退。

3. Held-out Tasks
验证是否学习到了通用能力，而不是记忆案例。

## 可复用方案

每次 Agent 改动生成 Change Proposal：

- 修改对象
- 失败原因
- 预期收益
- 潜在回归
- 必跑 Eval
- 回滚方案

## 对 Agent 工程的意义

未来高级 Agent Engineer 的核心能力不是写 Prompt，而是构建持续演进闭环。

对应架构：

Trace + Eval + Harness Version + Regression Gate + Deployment。

## 实践场景

适用于：
- Coding Agent
- 企业 Workflow Agent
- MCP Agent Platform
- 自动化运维 Agent

## 局限

自动优化容易过拟合，任何修改必须经过独立测试集验证。
