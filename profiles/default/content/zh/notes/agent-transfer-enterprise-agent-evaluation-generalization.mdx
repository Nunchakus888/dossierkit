## 核心判断

GDPevo 关注的问题不是 Agent 能否记住过去失败，而是能否学习可迁移规则。

## 背景

很多 Agent 优化只在历史失败集上测试，容易产生假提升：模型记住了案例，但面对新的业务组合仍失败。

## 核心思想

将任务拆成原子规则：

- 业务约束
- 操作流程
- 权限要求
- 数据关系

训练阶段只暴露部分规则，测试阶段重新组合，观察 Agent 是否理解规律。

## 工程启示

Agent Eval 不应只有：

历史 Case Pass Rate

还需要：

- 未见任务组合
- 新业务流程
- 新工具组合
- 新数据分布

## 可复用方案

建立 Agent Evaluation Matrix：

Known Task
-> Regression

Known Rule + New Combination
-> Generalization

Unknown Rule
-> Discovery Ability

## 实践意义

适用于：
- 企业 Copilot
- CRM Agent
- 数据分析 Agent
- 自动化工作流 Agent

## 对工程师的要求

重点从 Prompt 调优转向：

Task Modeling + Eval Design + Failure Analysis。

## 局限

企业真实流程复杂，规则抽象质量会直接影响评测价值。
