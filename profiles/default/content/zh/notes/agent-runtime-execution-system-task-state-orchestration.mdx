## 核心判断
Agent 的基础设施问题已经从模型推理转向动态执行管理。LLM 只是执行链中的一个节点，真正困难的是任务状态、工具调用、失败恢复和资源调度。

## 背景
传统 LLM 服务假设一次请求对应一次推理，而 Agent 任务通常包含规划、检索、工具调用、验证和多轮调整。性能瓶颈因此从 GPU 推理扩展到 CPU 调度、网络、状态管理和工具执行。

## 核心思想
Agent Runtime 应被视为动态 Workflow Engine：负责 Task 生命周期、State、Scheduler、Tool Execution 和 Recovery。

## 工程抽象
一个生产 Agent Runtime 至少包含：
- Task：目标与预算
- State：当前执行状态，而非聊天记录
- Execution Graph：动作与观察过程
- Tool Runtime：权限、执行、审计
- Recovery：失败分类与策略切换

## 实践方案
MVP 可以从 Task State Machine、Tool Registry、Trace 开始；进一步增加模型路由、预算控制、审批和沙箱。

## 关键认知
Agent 不是 LLM + Prompt，而是 Model、Runtime、Tools、State、Policy、Evaluation 的组合系统。
