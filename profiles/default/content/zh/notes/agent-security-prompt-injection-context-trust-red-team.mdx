**核心论点：当攻击系统能够跨目标积累策略并用少量查询适配新 Agent 时，静态关键词过滤和单次攻击集无法代表真实安全性；防御必须同时约束上下文的控制权与工具动作的授权。**

## 风险已经从“说错话”变成“做错事”

工具型 Agent 会把网页、邮件、仓库、检索结果和工具输出放入同一推理上下文。攻击文本无需直接窃取密钥；只要让模型把不可信内容当成高优先级指令，就可能改变文件、发送消息或污染长期记忆。

PIMiner 将 Prompt Injection 红队过程做成 Agent：它在一系列数据集与目标模型上构建策略库，测试时把策略迁移到未见模型，并以较小查询预算选择和改写攻击。安全评测由此从固定 Payload 集转为持续搜索问题。

## 论文证据与正确解读

论文报告，在每个测试样本大约 10 次目标查询的条件下，PIMiner 在 IPIArena 上对 Gemini-2.5-Pro、GPT-5.1、Claude-Sonnet-4.5 的攻击成功率分别达到 76.2%、61.9% 和 42.9%；在 AgentDojo 上分别为 86.7%、53.3% 和 40.0%。这些数字不能说明生产系统必然以相同比例失守，但明确表明策略能够跨目标迁移，固定规则会面对分布外变体。

更关键的因果链是：攻击成功经验进入策略库，策略选择减少无效试探，新目标反馈再次改写策略。防御若只复测旧字符串，测到的是样本记忆，不是系统边界。

## 防御架构：信息可以进入，权限不能随之进入

上下文中的每一段内容都应携带来源、信任等级与用途标签。外部文档可以作为事实证据，却不能授予发送、删除或授权权限。动作执行前由独立 Policy Engine 根据用户意图、工具风险、目标对象与数据范围重新判定，不能让同一个模型仅凭上下文自证授权。

```text
外部内容 → 来源与完整性标记 → 模型推理
                                  ↓
用户意图 + 组织策略 → 动作规范化 → 权限门 → 沙箱/工具
                                  ↓
                           回执、审计与告警
```

长期记忆写入也属于高风险动作：候选记忆要保留来源，经过去指令化、冲突检查和有效期控制；被攻击会话产生的内容不能自动晋升为规则。

## 红队与工程验证

评测应组合固定回归集、策略搜索、未见目标和真实工具链。指标不仅记录攻击文本是否被遵从，还要记录越权动作、接触的数据、持久化影响与人工审批是否被绕过。对高风险工具实施最小权限、参数白名单、隔离凭据和可撤销执行。

## 反例、局限与适用边界

攻击成功率依赖基准、目标模型、工具配置和成功定义，不能跨场景直接比较。自动红队也可能过拟合策略库或产生与真实业务无关的攻击。严格隔离会降低可用性；只读检索与生产写操作需要不同门槛。任何过滤器都不应被描述为彻底解决 Prompt Injection，安全来自多层失效隔离。

## 在七篇中的位置

Self-Evolving 与 GDPevo 说明系统会把经验变成持久状态，PIMiner提醒这种路径也可能固化攻击；Agent Runtime 提供策略执行、隔离与审计；Active-SWE 和 SuperScout 读取不可信仓库内容时必须保留来源；MCP Stateless 让 Gateway 在每次工具请求上重新执行身份与授权。
