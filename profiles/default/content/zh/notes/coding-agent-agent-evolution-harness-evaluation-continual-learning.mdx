## 核心判断
未来 Coding Agent 的竞争，不只是第一次任务完成率，而是 Agent 是否能从真实运行失败中提取规律，并通过受控迭代提升能力，而不是不断堆积 Prompt 补丁。

这类研究关注的不是让 Agent 自我修改，而是让 Agent 的演进过程具备软件工程中的可验证性。

## 背景问题
当前 Agent 优化通常是：发现失败 → 修改 Prompt / Tool / Workflow → 重新测试。

问题是，一次修复成功并不代表能力提升。很多优化只是针对某个案例形成局部规则，最终导致 Prompt 越来越复杂，但系统没有真正增强。

## 核心思想
将 Agent 优化看成持续学习系统：

Production Trace → Failure Analysis → Improvement Proposal → Regression Evaluation → Release

优化对象不再只是 Prompt，而是完整 Harness。

## Harness 的含义
Harness 是控制 Agent 行为的软件层，包括：

- Context Construction：决定 Agent 获取哪些信息。
- Planning：决定任务拆解方式。
- Tool Strategy：决定何时使用哪些工具。
- Completion Detection：决定什么时候结束。
- Recovery Strategy：决定失败后的恢复路径。

## 关键方法
Agent 失败必须归因，而不是简单记录失败。

失败可能来自：

- Model
- Context
- Tool
- Memory
- Planner
- Runtime
- Validation

不同原因需要不同修复。

## Agent Evolution Loop

Agent Execution
↓
Trace Collection
↓
Failure Classification
↓
Root Cause Analysis
↓
Generate Candidate Change
↓
Evaluation
↓
Release

## Eval 体系
不能只测试任务是否成功，需要三层：

1. New Capability：新的失败是否修复。
2. Regression：旧能力是否下降。
3. Generalization：是否学到了可迁移规律。

## 工程落地
第一阶段：建立 Trace、Failure Label、Eval。

第二阶段：Failure Cluster → 推荐 Harness Change。

第三阶段：Failure → Proposal → Eval → Deploy 半自动演进。

## 最终沉淀
Agent Evolution 不是 Prompt → Better Prompt，而是：

运行 → 观察 → 归因 → 修改 → 验证 → 发布。

复杂 Agent 系统的核心能力，不是一次生成质量，而是长期稳定变好的机制。
