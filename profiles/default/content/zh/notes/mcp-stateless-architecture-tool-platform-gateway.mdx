## 核心判断
MCP 走向 Stateless，不只是协议简化，而是职责重新划分：Agent Runtime 管状态，MCP 负责能力暴露和执行。

## 背景
早期 MCP 适合本地工具，但企业规模下 Session 状态会阻碍水平扩展、多区域部署和统一治理。

## 核心思想
将 MCP Server 设计为无状态服务，把 Task State、Memory、Approval 等交给 Agent Runtime 管理。

## 工程抽象
企业级 MCP 架构需要 Gateway 层：
- Tool Discovery
- Authentication
- Authorization
- Routing
- Trace
- Version Management

## 实践方案
Tool 不应只描述 name 和 schema，还需要风险、权限、副作用、成本和可靠性信息，供 Runtime 决策。

## 关键认知
MCP 解决的是 Agent 如何连接外部能力，而不是 Agent 如何思考。生产系统需要 Runtime、Policy 和 Tool Platform 的组合。
