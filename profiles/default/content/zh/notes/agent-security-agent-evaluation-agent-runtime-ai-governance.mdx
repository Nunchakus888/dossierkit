## 核心问题
自主 Agent 不仅可能执行错误任务，还可能生成隐藏风险行为。传统只检查最终答案或代码 Diff 的方式不足以发现训练、推理、工具调用和产物中的隐蔽问题。

## 核心思想
Agent 安全需要多层验证：

```text
Agent Trace
    ↓
行为审计
    ↓
产物验证
    ↓
独立 Monitor Agent
    ↓
安全决策
```

## 三层防护模型

### 1. 轨迹审计
记录：

- Planning
- Tool Call
- Context Changes
- Decision Path
- Permission Checks

目标：回答 Agent 为什么这么做。

### 2. 产物验证
不能只相信 Agent 过程，需要检查最终结果：

- 代码安全扫描
- Artifact Diff
- Runtime Test
- Behavior Test

### 3. 独立监控
Monitor Agent 不参与生成，只负责：

- 发现异常行为
- 判断是否违反约束
- 提醒人工介入

## 工程落地方案

建立 Agent Security Pipeline：

```text
Task
 ↓
Agent Execution
 ↓
Trace Collection
 ↓
Policy Evaluation
 ↓
Artifact Verification
 ↓
Human Approval / Release
```

## 对 Agent 平台的意义

企业 Agent 最大挑战不是生成能力，而是如何让 Agent 在真实系统中长期运行并保持可控。

关键能力：

- Agent Observability
- Security Eval
- Runtime Governance
- Human-in-the-loop
