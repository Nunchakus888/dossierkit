工具应承担配置与协调的复杂性，让人把时间用在目标、判断和结果上。

十万大山信息服务工作室的 Cowork 产品分享，围绕数字分身、对话式自配置和连续工作展开。落地从本人和身边用户的个人任务开始，再进入中小团队的运营工作：围绕活动配置、人群画像与流量策略，用一项范围明确的任务把方案、执行和复盘接起来。业务知识与工作方法逐步积累，能力也随实际需求延伸到更多平台和多人协作。

## 一句话配置自己的工作伙伴

“做我的运营数字分身。沿用这份品牌规则和预算，日常整理数据、准备活动配置，发布和预算调整交给负责人确认。”

Cowork 的自配置设计把这段要求整理成角色、知识来源、工作规则、可静默推进的任务范围与负责人确认项，展示具体变更后使用。用户无需先选择模型、思考程度或场景模式。执行中按需编写代码，把验证有效的步骤沉淀为可复用 Skill，继续通过对话调整方法。角色与工具可以配置，权限由有相应职权的人授予。

## 产品场景：各角色的数字分身，带着上下文工作

数字分身了解所负责的业务，带着角色背景、知识、历史方法与明确授权处理日常任务。群里贴出“回流活动触达下降，转化也低于预期”的 Case，直接 @Cowork，就能关联人群规则、渠道数据、配置变更与已授权日志，开始排查。

运营数字分身核对活动目标、人群与投放规则，研发数字分身追踪触达链路、数据上报和近期变更，测试数字分身复现异常并核对数据口径。各角色在已有授权内并行工作，Cowork 合并证据、推进任务。需要关键决定或超出授权的动作时，具体原因、影响与处理方案交给对应负责人；获准后继续执行与核对。

更多日常工作在有限授权内静默推进。打开后的工作摘要可以呈现“10 个 Case 已处理、3 个客诉已梳理、7 个 Bug 已排查”，并提供结果、证据和处理记录。这里的数字是产品场景示意，用于说明汇总体验。

人从逐项找人、催办和确认，转向打开看结果、关键时刻做决定。处理过程中积累的知识、结论与记录，也成为下一次工作的起点。

## 第一步：离开电脑，工作也能继续

任务在电脑上开始，人却不能一直坐在电脑前。个人起步场景聚焦这段连续执行：在电脑上准备回流活动，提供活动目标、用户与渠道数据；出门后手机说一句“继续刚才的活动，补上这份渠道数据，按原来的预算准备配置，把预览发到这里”。

Cowork 的设计把资料、上下文、进度与执行留在云端。用户用手机补充信息、查看进度，必要时确认关键动作；云端按需处理网页、文件与数据，人群规则、活动方案和配置预览回到当前入口。对于已上传资料、授权数据和云端可运行工具支持的任务，原来的电脑无需保持在线，也无需从手机远程连回去。

从本人和身边用户的日常工作开始，把这段连续执行用起来。手机、电脑 Web 起步，微信、飞书等熟悉的渠道按开放能力逐步接入。仅本机可用的软件、设备或资料需相应连接；客户端访问仍需要网络，实际使用以接入范围和任务记录为依据。

## 换平台，也带着自己的工作积累

在已接入的 Agent 平台，说一句“接着刚才的回流活动，用新数据调整人群，按我的工作方法完成剩下的配置”。同一个数字分身带着角色、已授权知识、工作记忆、处理记录、结论和未完成步骤继续，保留用户原来的模型与业务流程。

Codex 和 Claude Code 都支持 MCP，为标准能力接入提供基础。[Codex 官方文档](https://developers.openai.com/codex/mcp)、[Claude Code 官方文档](https://code.claude.com/docs/en/mcp)。WorkBuddy 等平台按各自开放接口适配；身份绑定、任务关联与有效授权决定可携带的上下文。

缺少网页或文件操作能力的 Agent，可按接口调用 Cowork 的云端执行能力，随后取回证据、文件与状态，在原流程继续交付。按需 Coding，把验证有效的方法整理为 Skill。跨平台扩展随实际需求推进，接入以真实兼容验证为准。

## 团队落地：把运营方案推进到执行

中小团队的运营工作包括活动配置、人群画像、流量策略，也包括活动效果异常的排查。Cowork 围绕同一个业务目标，把分散的数据、业务规则与执行操作串起来。

以一场回流活动为例：“为近 30 天未访问、过去有互动的用户准备回流活动。沿用品牌规则与预算，给我人群、方案和配置预览。”这里的时间范围是示例条件，实际按客户业务定义。

- **人群画像**：关联已授权的行为、标签与历史反馈，梳理沉默原因和人群差异，给出筛选规则与分群依据。
- **活动配置**：准备权益、素材、时段与业务规则，操作已接入的后台，生成配置预览，由负责人确认发布并核对结果。
- **流量策略**：结合预算、渠道与历史表现，准备渠道分配和触达频次，跟踪效果并给出调整依据。

第八页用 Mermaid 流程图展示协作：业务目标交给 Cowork，Cowork 携带角色上下文拆解任务、派发指令；运营、数据和投放分身在授权范围内各司其职，汇总方案与配置预览。负责人确认发布与预算后，Cowork 下发获准指令，各分身执行、核对并跟踪，最终汇总交付。已有授权内的日常动作静默推进，关键动作由对应负责人决定。

交付包含人群规则、活动配置、投放方案与复盘。出现触达、转化或数据口径异常，就沿同一份上下文继续排查，关联配置、数据和日志，找出已证实事实与待确认项。负责人掌握发布与预算调整的职权，数字分身推进已授权的分析和执行。

运营可以减少导表、搬资料、跨系统录入、找人确认和重复交代背景，把时间留给业务判断与创意。这份交付既要有可读的方案，也要有配置预览、执行记录与结果依据。

## 一次运营任务，沉淀一套可复用的方法

每做一场活动，都可以留下下一次能用的东西：品牌规则、人群口径、执行步骤与效果复盘。验证有效的方法整理成 Skill，换一批人群、换一个渠道，也能从已有积累开始。

落地从个人任务进入范围明确的团队交付，先约定数据来源、权限与交付标准，再把人群、配置、投放和复盘接起来。用真实客户任务建立合作，比较同类任务的完整人工耗时，包含资料整理、核对、修订和返工，由业务负责人确认交付可用。实际使用、复用与付费分别记录。

商业表达围绕任务量和约定服务范围：客户为可用交付和解决问题的能力付费，计费周期与价格随实际需求约定。从一项客户愿意付费的运营工作开始，积累可复用的方法，再延伸到更多业务场景。

## 产品竞争力

竞争力贯穿整个任务链：配置通过对话完成，数字分身在有限授权内静默处理工作，已有平台与 Agent 继续使用，积累的上下文持续复用。个人化与持续服务参考了 [Muse 官方产品设计](https://introducing.muse.ai/)，分享重点放在 Cowork 的自配置、角色上下文、连续工作与范围明确的业务交付。

## 十万大山的愿望

George 有十年软件开发经验、大厂研发经历，专注企业 AI Agent 解决方案。“十万大山”承载着让技术越过重重使用门槛的愿望：从改善一个人的工作开始，让更多人拥有过去需要一个团队才能具备的能力，随时随地，在自己熟悉的平台继续工作。

以上产品场景与落地路线用于说明设计理念及使用方式，非已完成客户项目或已取得的收入。工作摘要数字为示意，非实测业绩。数字分身、多人角色编排、持续工作、跨入口记忆、自配置和对外服务按实际接入范围使用；静默工作保留可追踪的进度与记录，执行在有效授权与对应业务系统的权限内推进。
