工具应承担配置与协调的复杂性，让人把时间用在目标、判断和结果上。

十万大山信息服务工作室的 Cowork 产品分享以两类场景展开：各角色的数字分身在有限授权内静默处理工作，以及同一数字分身带着已积累的上下文跨平台继续执行。约五分钟的分享围绕对话式自配置、业务知识、工作记忆与云端执行，说明如何减少重复配置、人工转交和重复排查。

## 一句话配置自己的工作伙伴

“做支付业务的数字分身，先核对回调和近期变更。用这份业务说明，日常排查静默处理，修复由负责人确认。”

Cowork 的自配置设计把这段要求整理成角色、知识来源、工作规则、可静默推进的任务范围与负责人确认项，展示具体变更后使用。用户无需先选择模型、思考程度或场景模式。执行中按需编写代码，把验证有效的步骤沉淀为可复用 Skill，继续通过对话调整方法。角色与工具可以配置，权限由有相应职权的人授予。

## 案例一：各角色的数字分身，带着上下文工作

数字分身了解所负责的业务，带着角色背景、知识、历史方法与明确授权处理日常任务。群里贴出一笔已支付、页面仍显示待付款的订单，直接 @Cowork，就能关联订单、支付状态、日志与近期变更，开始排查。

运营数字分身整理反馈和影响，研发数字分身追踪链路并准备修复，测试数字分身复现和验证。各角色在已有授权内并行工作，Cowork 合并证据、推进任务。需要关键决定或超出授权的动作时，具体原因、影响与处理方案交给对应负责人；获准后继续执行与核对。

更多日常工作在有限授权内静默推进。打开后的工作摘要可以呈现“10 个 Case 已处理、3 个客诉已梳理、7 个 Bug 已排查”，并提供结果、证据和处理记录。这里的数字是产品场景示意，用于说明汇总体验。

人从逐项找人、催办和确认，转向打开看结果、关键时刻做决定。处理过程中积累的知识、结论与记录，也成为下一次工作的起点。

## 案例二：带着已有上下文，跨平台继续工作

昨天在群里处理订单 Case，今天打开 Claude Code，说一句“接着昨天的 Case 查”。Cowork 的跨平台设计让同一数字分身带着角色、负责业务、已授权知识、工作记忆、证据、排查结论、处理记录和任务进度接手。加入新的反馈，从未完成的步骤继续，结果交回原 Agent。

Codex 和 Claude Code 都支持 MCP，为标准能力接入提供基础。[Codex 官方文档](https://developers.openai.com/codex/mcp)、[Claude Code 官方文档](https://code.claude.com/docs/en/mcp)。

已有 Agent 可通过接口调用 Cowork 的网页、文件和云端执行能力，在原界面和流程继续交付。Coding 按任务需要使用，经过验证的方法可整理为 Skill。跨平台保留已积累的业务理解和任务状态，减少重新交代背景、搬运资料与重复排查。

飞书、WorkBuddy 等入口按各自开放接口适配；标准协议支持、身份绑定、任务关联与授权共同决定实际接入范围。兼容标准的 Agent 可以按接口对接，保留自己的模型和业务流程；上下文延续以已绑定身份与关联任务为基础。

## 产品竞争力与商业路径

竞争力贯穿整个任务链：配置通过对话完成，数字分身在有限授权内静默处理工作，团队围绕关键判断协同，已有平台与 Agent 继续使用，已经积累的上下文持续复用。个人化与持续服务参考了 [Muse 官方产品设计](https://introducing.muse.ai/)，分享重点放在 Cowork 的自配置、跨角色协作和跨平台能力复用。

企业团队购买场景接入与持续服务，Agent 伙伴按任务调用，个人订阅自己的工作伙伴。同一套角色与方法服务不同客户，商业价值来自更少的人力阻塞、更低的平台接入成本与持续的方法复用。

## 十万大山的愿望

George 有十年软件开发经验、大厂研发经历，专注企业 AI Agent 解决方案。“十万大山”承载着让技术越过重重使用门槛的愿望：从改善一个人的工作开始，让更多人拥有过去需要一个团队才能具备的能力，随时随地，在自己熟悉的平台继续工作。

以上两类案例为产品场景设想，用于说明设计理念与使用方式。工作摘要数字为示意，非实测业绩。数字分身、多人角色编排、持续工作、跨入口记忆、自配置和对外服务按实际接入范围使用；静默工作保留可追踪的进度与记录，执行在有效授权与对应业务系统的权限内推进。
