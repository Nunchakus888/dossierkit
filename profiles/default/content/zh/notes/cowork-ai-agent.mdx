工具应承担配置与协调的复杂性，让人把时间用在目标、判断和结果上。

十万大山信息服务工作室的 Cowork 产品路演以两类场景展开：企业群里的协同排查，以及已有 Agent 的跨平台能力接入。约五分钟的分享围绕对话式自配置、角色上下文、业务知识与云端执行，说明如何减少重复配置、人工转交与平台迁移。

## 一句话配置自己的工作伙伴

“你负责订单问题排查，先核对支付回调和近期变更。使用这份业务说明，报告发回项目群，修复由支付负责人确认。”

Cowork 的自配置设计把这段要求整理成角色、知识来源、工作规则与负责人确认项，展示具体变更后使用。用户无需先选择模型、思考程度或场景模式。执行中按需编写代码，把验证有效的步骤沉淀为可复用 Skill，继续通过对话调整方法。角色与工具可以配置，权限由有相应职权的人授予。

## 案例一：群里贴 Case，@Cowork 协同排查

一笔订单已支付，页面仍显示待付款。群里贴出 Case，直接 @Cowork，要求定位原因、梳理影响范围并给出处理方案。

Cowork 的产品场景让分析在已有授权内开始：关联订单、支付状态、日志与近期变更；运营角色整理影响，研发角色追踪链路并准备修复，测试角色复现和验证。每个角色带着自己的业务背景、职责和访问范围。涉及修复与发布时，具体动作交给对应负责人授权，AI 再继续执行、核对结果并汇报。

最终交付包括原因证据、影响范围、修复内容和验证结论。试点关注从问题出现到结果交付的耗时，以及人工找人、转派和催办的次数。

## 案例二：留在原平台，接入自己的 Cowork

Codex 和 Claude Code 都支持 MCP，为标准能力接入提供基础。[Codex 官方文档](https://developers.openai.com/codex/mcp)、[Claude Code 官方文档](https://code.claude.com/docs/en/mcp)。

Cowork 的服务化设计让已有 Agent 提交任务，关联同一角色、已授权知识与处理记录，调用网页、文件和云端执行能力，随后取回证据、文件与状态，在原流程继续交付。跨平台复用角色、知识与方法，能够减少重建背景和搬运资料的成本。

飞书、WorkBuddy 等入口按各自开放接口适配；标准协议支持、身份绑定、任务关联与授权共同决定实际接入范围。兼容标准的 Agent 可以按接口对接，保留自己的模型和业务流程。

## 产品竞争力与商业路径

竞争力贯穿整个任务链：配置通过对话完成，团队按角色直接推进工作，已有平台与 Agent 继续使用。个人化与持续服务参考了 [Muse 官方产品设计](https://introducing.muse.ai/)，分享重点放在 Cowork 的自配置、跨角色协作和跨平台能力复用。

企业团队购买场景接入与持续服务，Agent 伙伴按任务调用，个人订阅自己的工作伙伴。同一套角色与方法服务不同客户，以问题处理耗时、人工转交次数、接入成本、持续复用和实际付款检验价值。

## 十万大山的愿望

George 有十年软件开发经验、大厂研发经历，专注企业 AI Agent 解决方案。“十万大山”承载着让技术越过重重使用门槛的愿望：从改善一个人的工作开始，让更多人拥有过去需要一个团队才能具备的能力，随时随地，在自己熟悉的平台继续工作。

以上两类案例为产品场景设想，用于说明设计与试点方向。多人角色编排、跨入口记忆、自配置和对外服务以实际接入验收界定交付范围；客户成果与效率指标以真实试点记录为依据。
