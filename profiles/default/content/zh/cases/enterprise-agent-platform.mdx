## Positioning

这个案例用于承载主攻方向：企业级 Agent 平台架构负责人。后续补真实项目时，重点不是写“做了一个 Agent”，而是证明你拥有平台边界、核心模块、上线门槛和跨团队交付的所有权。

## Architecture Scope

平台证据建议围绕五层展开：

1. Agent Runtime：任务状态、计划执行、重试、超时、人工接管和失败恢复。
2. Tool / MCP / Skills：工具注册、schema 管理、版本控制、权限绑定和调用审计。
3. Permission & Audit：身份、租户、数据权限、敏感操作确认和审计日志。
4. Evaluation Harness：离线回放、golden set、过程断言、工具副作用检查和发布门禁。
5. Observability & LLMOps：trace、日志、指标、模型路由、缓存、延迟和成本分析。

## Senior Ownership

高阶表达要突出：

- 不是接一个工具，而是定义工具接入、权限审批、运行时授权和审计边界。
- 不是调 prompt，而是建立 prompt、工具 schema、模型版本和 RAG 策略的发布门禁。
- 不是做单点应用，而是把能力沉淀为多个业务流程可复用的平台资产。
- 不是只交付功能，而是对稳定性、成本、质量和业务结果负责。

## Evidence To Add

后续真实项目实践应补：

- 接入的核心业务流程，以及原流程痛点。
- 工具数量、业务系统数量、任务量、用户范围和上线阶段。
- 你负责的架构决策、核心模块和跨团队推进事项。
- 任务成功率、人工接管率、工具误调用率、回放通过率、延迟、成本和稳定性指标。
- 业务 ROI，例如流程耗时、人效、错误率、交付周期或客户满意度变化。

## Interview Angle

这页的表达重点是：我能把 Agent 从 demo 推进到企业核心流程，建设平台能力、治理边界和质量闭环，而不是只做应用层功能拼装。
