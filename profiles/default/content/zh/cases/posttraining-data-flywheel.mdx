## 这个案例需要证明什么

这个案例用于证明你理解 Agent 质量提升不只靠 prompt，也需要把线上失败转成可复盘、可评测、可标注、可训练的数据资产。它适合支撑后训练数据闭环、评测体系、LLMOps 和 Agent 平台负责人岗位。

这里不需要伪装成基座模型训练专家，重点是证明你能在应用层和算法层之间搭桥。

## badcase 分类框架

建议按以下类别沉淀：

- 工具选择错误：选错工具、漏调工具、重复调用。
- 参数错误：字段映射错误、单位错误、时间范围错误、权限参数错误。
- 任务分解错误：计划顺序不合理、子任务遗漏、无法恢复失败。
- 知识与上下文错误：召回缺失、上下文污染、长上下文遗忘。
- 业务规则错误：违反流程、审批、合规、风控或客户策略。
- 输出质量错误：幻觉、拒答不当、格式错误、不可执行建议。

## 数据闭环框架

一条成熟链路可以拆成：

1. Trace 采集：保留用户目标、上下文、工具、参数、中间状态和最终结果。
2. 失败归因：把 badcase 标准化分类，区分模型、工具、数据、产品和流程问题。
3. 样本入库：进入 replay eval、golden set、偏好对或人工复盘池。
4. 标注规范：定义 chosen/rejected、原因标签、风险等级和业务约束。
5. 训练接口：为 SFT、DPO、偏好优化或 prompt/工具 schema 修正提供数据。
6. 发布门禁：用回放集和线上指标验证新版本是否真正改善。

## 应补充的真实证据

后续项目实践建议补：

- badcase 规模、分类数量、标注参与角色和质检方式。
- 评测集大小、覆盖任务类型、回放通过率和回归发现数。
- 数据进入 prompt、工具 schema、RAG、模型路由或训练实验后的效果。
- 与算法、产品、工程团队协同的流程和交付节奏。

## 面试表达角度

这个案例的重点是：你能把生产 Agent 的失败变成产品、工程和模型共同可用的数据语言，让 Agent 质量迭代从“凭感觉调 prompt”变成有样本、有指标、有发布门禁的闭环。
