## Goal

Convert production task traces into offline replay evaluations so teams can understand risk when changing prompts, tool schemas, or model versions.

## Sample design

Each sample should include the user goal, business context, available tools, permission boundary, expected intermediate behavior, final output assertions, tool side-effect checks, and human fallback policy.

## Metric layers

Evaluation should cover at least three layers:

- Process metrics: tool choice, parameter validity, permission match, step order, and recovery strategy.
- Outcome metrics: task success, actionability, formatting correctness, and business-rule compliance.
- Operating metrics: human handoff rate, average latency, token cost, failure distribution, and regressions caught.

## Release gate

Every change to prompt, tool schema, RAG strategy, model version, or system permission should run fixed replay sets. High-risk workflows need staged rollout, and new production badcases should flow back into the golden set.

## Lesson

Final-answer checks miss important risks. Agent evaluation must inspect process, tools, side effects, and recovery strategy.
